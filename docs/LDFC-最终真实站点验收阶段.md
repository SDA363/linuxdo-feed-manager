## 9. P2-A 修复结果

**问题**：Guest 模式下每次同步都请求必然 403 的 `/unread.json`（实测 3 次路由切换 = 3 次 403）。

**修复**：`site/discourseAdapter.js` 的 `fetchUnreadList()` 增加早返回：

```js
if (!window.LDFCIdentity.current().loggedIn) return Promise.resolve(null);
```

放在适配器内部而不是调用方，**保证任何调用路径都不会再发出这个无用请求**。

**影响范围**：只减少一个无用请求。不影响 Guest 本地兜底、不影响登录态新回复发现、不改产品规格。

**验证**：

| | 修复前 | 修复后 |
|---|---|---|
| Guest 路由切换 `/unread.json` 请求数 | 3（全部 403） | **0** |
| 本地回归 | 49 / 49 | **50 / 50** |

新增回归测试：`PASS：未登录时不请求必然 403 的 /unread.json（实际请求 0 次）`
真实站点复测：`/unread.json 请求次数: 0`（身份仍为 `guest` / `ldfc__guest`）

## 10. 已知观察项

### P2-观察：完成确认后本地缓存的 `unreadPosts` / `lastReadPostNumber` 未立即更新

| 项 | 内容 |
|---|---|
| 现象 | 新回复读完后，记录里 `unreadPosts` 仍为 `3`、`lastReadPostNumber` 仍为 `57`；而服务器实际已是 `last_read=60 / highest=60 / unread=0` |
| 当前影响 | **无已验证的用户可见影响** —— `newReplyPending` 已正确清除，UI 无异常 |
| 为什么**部分**不会出错 | 若 Topic 已离开 NEW_REPLY（unread 归零被清除），下一次有新回复时走 `markNewReply` **全量写入** → `lastReadPostNumber` 会被刷新 ✓ |
| **实测发现的缺口** | 若 Topic **持续留在 NEW_REPLY**（用户没读完），`discoverNewReplies` 只更新 `unreadPosts`，**不更新 `lastReadPostNumber`** → 「第一条未读预览」可能停在一个用户已经读过的楼层 |
| 实测证据 | 首次发现 `{unread:4, lastRead:2}` → tracking 给出新阅读位置 4 后再发现 → `{unread:2, lastRead:2}`（**未读刷新了，lastRead 没刷新**）；<br>对照：清除 newReply 后重新发现 → `{unread:5, lastRead:9}`（全量刷新 ✓） |
| **表述修正** | 此前报告里"下一轮 discovery 会覆盖过期缓存"的说法**过于绝对**。准确表述是：**只对"已离开 NEW_REPLY 后重新发现"成立，对"持续留在 NEW_REPLY"不成立** |
| 性质 | **P2 / 已知缺口**，不是 P0/P1 |
| 本轮处理 | **不改代码**（按指示：核心功能已验证通过，不为缓存一致性问题扩大改动）。已加入回归检查项，`lastRead` 不刷新这一缺口被**显式断言并标注**，不会随时间被遗忘 |
| 后续触发条件 | 若证明它会造成**用户可见**错误（例如预览长期停在已读楼层），再单独处理 |

### 其他观察

- `/session/current.json` 每次整页加载请求 1 次（账号身份解析，设计如此；Phase 0 已确认 `#data-preloaded` 里也有 `currentUser`，属可选优化）
- 首次用全新 profile 无头启动真实站点可能遇到 Cloudflare 挑战页；改用可见窗口后直接通过（**未做任何规避**）

## 12. 非 V1 目标

### 实时新回复的即时发现

当前 V1 设计是**被动发现优先**：利用打开 Linux.do、刷新、切换列表、
从 Topic 返回等**自然时机**检查，并**明确禁止后台高频轮询**。

因此 V1 的目标**不是**"新回复发生后立即推送"。

```
“已有未读状态 → NEW_REPLY → 阅读完成”完整闭环     ✅ 真实站点 8/8 已验证
“新回复发生后的即时发现延迟”                     【未专门验证 / 非 V1 实时目标】
```

**不作为 V1 阻塞项。** 这两件事不能混为一谈 —— 前者是产品行为，后者是时效性指标。
