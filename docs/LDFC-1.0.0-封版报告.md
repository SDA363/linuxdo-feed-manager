## 8. 已知观察

### 观察 1：tracking 的未读语义比 `/unread.json` 宽

```
topicTrackingStates 报告"有未读"的行:  218
/unread.json 报告:                     30
```

原因：`site/trackingState.js` 的 `unreadFrom()` 把 `last_read_post_number = null`
当成"整帖未读"（`unread = highest`）。

**已有防护**：发现层要求 tracking 那一路的 `lastReadPostNumber !== null`，
否则"从未读过"的 Topic 会被凭空判成有新回复。
**已有回归断言**：fixture 106（修复前会失败）。

`unreadFrom()` 本身未改 —— 它仍可用于其它展示场景。**当前不构成用户可见错误。**

### 观察 2：`/session/current.json` 每次整页加载请求 1 次

账号身份解析所需。Phase 0 已确认 `#data-preloaded` 里也有 `currentUser`，
理论上可省掉这次请求 —— 属**可选优化**，不是缺陷。

### 观察 3：全新 profile 无头启动真实站点可能遇 Cloudflare

环境问题，非扩展问题。改用可见窗口即可通过。**全程未做任何规避**（无刷新循环、无改 UA/指纹）。

### 观察 4：测试动作会触发自动已读

真实站点测试中点击 Topic 会触发**正常的**自动已读。本地测试记录已按 id 精确清理；
服务端阅读位置不可逆（例如 Topic 2899328 与 2736395 已被读完，属授权范围内）。
