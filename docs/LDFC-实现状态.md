## 三、与规格的已知偏差（有意为之）

| 项 | 规格 | 实现 | 原因 |
|---|---|---|---|
| 消失效果 | "Topic 从 DOM 移除" | 动画后用 `display:none` 隐藏 | 列表行由 Ember（Discourse 前端框架）管理，物理删除会导致重渲染报错 |
| DOM 防重复标记 | 用 `data-ldfc-processed` 标记 | 用"按钮是否已存在"判断 | 标记写在元素上，Ember 复用元素时会误判为已处理，反而丢按钮 |
| 搜索结果页 | 只要求"不过滤" | 不过滤、不接管点击；**注入行操作按钮**（V1.1 起） | 用户要求搜索页也能直接标记；按钮只做显式标记，不改变列表内容与链接行为 |
| 技术栈 | 推荐 TS + Vite | 纯 JS，无构建步骤 | 当前规模下更易直接调试；未使用任何 `chrome.*` API |
| 元数据 | 含 category / author | 存 `categoryId` + 最后回复人 | 分类名需要额外映射请求，列入 Backlog |
| 自动补位参数 | "必须限速、必须有限" | 当前取 2 页 / 3 秒的保守初值 | 规格未指定数值，属【实现候选】，待 Phase 0 后定稿 |
| 未感兴趣区按钮 | 用户原话含 `[× 不感兴趣]` | 只保留 `[移回主信息流]` + `[移入…]` | 已确认的 UI 取舍：在已屏蔽区再放屏蔽按钮无作用；`[移入…]` 可把它改到其他池 |

## 四、实现层面的已知行为特征

以下都是**【实现候选】带来的行为**，**不是产品需求**，Phase 0 后可能被消除：

- **未登录模式的新回复首次判定要等下一轮同步。**
  当前 fallback 需要先建立本地阅读基线（记下打开 Topic 时的最高楼层），
  因此新回复最早在**下一次自然同步**时才会被发现。
  若 Phase 0 发现原站对匿名访客提供可直接使用的阅读 / 未读信息，
  **应当优先改用原站机制，并消除这个额外延迟。**

- **「主信息流」计数是当前列表页里未处理的行数**，不是全站总数。

- **新回复预览需要额外请求。** 护栏：只在「新回复」面板打开时抓、
  每次最多前 10 条、两次间隔 ≥1.2 秒、结果落库只抓一次。
  Topic 详情接口默认只返回一段楼层窗口，跨窗口时用楼层流索引补取。

- **切换 linux.do 账号后必须刷新页面。** 命名空间（`user-<id>`）在页面加载时
  解析一次并缓存到当前页面会话；登录/切号后不刷新，扩展会继续用上一个命名空间
  （或 `guest`）的数据库，看起来像"数据不见了"。云同步同理，会读写错误的文件。

- **云同步不是实时的。** 打开站点自动 pull 一次（每页面会话一次）+ 标记后
  debounce 10 秒自动 push；另一台设备要看到变化，需要刷新页面或点「立即同步」。
  没有轮询、没有长连接（AC-030 约束）。

- **列表页的请求量与正常浏览基本持平（2026-11-01 真实站点实测，游客身份）。**
  一次列表页加载插件只发 2 个 XHR：`/session/current.json`、`/latest.json`；
  游客不请求 `/unread.json`（P2-A）。同一次加载里站点自身与 Cloudflare 另有
  `/srv/pv`、`/cdn-cgi/rum` 等 4 个请求，与插件无关。
  悬停 5 行、每行停留 0.5 秒 → 5 个 `/n/-/<id>.json?sort=old`（悬停预取；
  500ms 冷却只合并密集扫过）；**静置 20 秒 → 0 个请求**，确认没有轮询。
  插件自身代码没有轮询定时器（vendored 引擎里的 2 个 `setInterval` 是阅读计时
  与本地 flush，不发网络）。
  `/n/-/<id>.json` 是第三方脚本作者的嵌套树接口，不是 Discourse 官方前端主路径，
  只在悬停（预取）和点开预览时出现。
  **登录态下的请求数未在真实站点统计**（lab profile 在 linux.do 上已是游客）。

- **手动「立即同步」会立刻重绘列表与计数**（V1.1.1 起）。此前只合并数据不重绘，
  真实使用中被误判成"没拉到"。

**远程文档格式（schema 5）**

- 体积构成实测（真实 283 条记录）：`title` 41.8%、`updatedAt` 13.0%、`topicId` 9.5%、
  `lastPostedAt` 7.5%、`basePool` 5.5%，其余字段合计 22.7%。
- 第一层（schema 2）紧凑编码：短键、设备字典 + 下标、省略默认值
  （`inNewReply:false` / `unreadPosts:0` / `enteredPoolAt === updatedAt` /
  `createdAt === updatedAt`）、空值（`null`/`""`）不写、池名单字母 `h/s/r/x`、
  占位 `slug:"topic"` 不写、墓碑压成数组对。
- 第二层（schema 4）：行改定长数组（列序写在 `cols` 里）、有限数字时间戳转
  base36 并加 `~` 前缀、然后再 gzip；文件直接是 gzip 字节，不套 base64。
- schema 5 = schema 4 + 行末两列 `nm`（通知手动接管档位）/ `nma`（接管时间戳，
  base36）。未接管过的记录两列为空，压缩后增量可忽略。
- 结果：**58.5 KB → 42.7 KB（schema 2）→ 23.6 KB（schema 3）→ 17.3 KB（schema 4）**，
  真实 294 条数据往返逐字节一致。
- 读端仍接受 `schema: 1/2/3/4`，写回统一升到 schema 5；新文件被旧版扩展读到时会明确报「schema 不兼容」
  并中止本次同步，不会写坏数据。运行时缺少 `CompressionStream` 时写入明文 JSON，功能不失效。
- 两个踩过的坑（已固化成单测）：
  1. `lastPostedAt` 是混合类型（毫秒数 / ISO 字符串），无差别 `parseInt(x, 36)`
     会把 `"2026-10-31T…"` 静默解析成 `30191`；
  2. 紧凑行的列里漏掉 `d`（deviceId 下标）时，所有记录会退回 `devices[0]`。
- 合并语义**没有改变**：LWW、tie-break、墓碑先后、预览/读进度不参与新旧判定，
  全部沿用原实现；这几轮只改"怎么写到远端"和"怎么读回来"。
- 通知「手动接管」标记（`notifyManualLevel` / `notifyManualAt`）用**独立时间戳**合并，
  不参与池子 LWW、不改 `updatedAt`，因此不会把记录顶到池子最前；
  `level = null` + 有 `at` 表示用户显式「跟随信息池」，这个清除同样会同步。

**未做**：S3 Google Drive（OAuth + AppData 读写）；油猴环境下的云同步
（无扩展后台，设置面板只显示说明）。真实坚果云已由用户手工联调通过，
但没有自动化。

**验证边界（不要误读为已验）**：

- **授权弹窗的点击路径没有自动化证据，但已有人工证据。** `chrome.permissions.request`
  会拉起 Chrome 自己的确认气泡，headless 环境下气泡不出现、回调不返回，无法自动化；
  2026-10-31 用户已在真实桌面 Chrome 上点通（`dav.jianguoyun.com` 授权成功）。
- 自动化端到端里「域名已授权」之所以直接成立，是因为 `prepare-probe-ext.js` 把
  `http://127.0.0.1/*` 写进了**必需** `host_permissions`（探针页与 WebDAV 同源），
  并不是点击授权页得到的。`chrome.permissions.remove` 对该来源会返回
  "You cannot remove required permissions."
- 真实坚果云链路（配置 → 授权 → 测试 → 拉取 → 推送 → 另一 profile 拉取）
  由用户手工验证，**未固化成自动化**。

  鼠标离开面板 220ms 后自动收起（留出指针在球与面板之间移动的时间）；
  点过面板里的按钮后「钉住」，移开鼠标也不收；点面板外部或按 Esc 收起。
- **悬浮球是唯一的位置基准**（`{ left, top }` 存球左上角）：面板收起态被
  `transform` 压到 52×52，与球完全重合；展开时从面板与球贴合的角连续放大到
  完整尺寸。方向由球心相对视口中心决定 —— 右半屏向左、左半屏向右，
  下半屏向上、上半屏向下。收起就是反向缩回同一颗球，球本身不会跳到别处。
- 已移除「收起 ⟩」按钮：收起方式改为「再点一次悬浮球 / 移开鼠标 /
  点面板外部 / Esc」。展开态球在前 120ms 淡出，由面板接管视觉；
  收起时面板先缩回，球在动画末段才浮现，避免中途看到两个图标。
- **池子按钮是 toggle**（V1.1.1 起）：再点一次当前已打开的池子＝收起，
  和设置按钮完全一致；点其他池子＝直接切换。判断条件是
  `activePool === 目标池 && !sheet.hidden && state !== "closing"`，
  收起动画进行中不会误判成"又打开一次"。
- 悬浮球图标改为**「信息流三行」**（三条横线 + 右侧圆点，内联 SVG）。
  圆点必须写 `style="fill:currentColor;stroke:none"`——
  `.ldfc-nav-fab-glyph` 的 `fill:none` 会盖掉 presentation attribute，
  不写内联样式就只剩三条线。
- 图标是内联 SVG 的堆叠层（不是 emoji），配 squircle 圆角 + 玻璃拟态
  （径向高光 + 渐变 + 内高光 + 外阴影）；图标→面板全程只做
  `transform` / `border-radius` / 内容透明度，不触发布局重排。
- 收起态显示「新回复」数量徽标，收起不等于把核心功能藏起来。
- 收起态可拖悬浮球；展开态可拖面板标题或其他非按钮区域。
  移动超过 6px 才算拖动，拖动结束会吞掉随后的那次 `click`，不会顺手开合面板；
  拖动途中会取消悬停展开，避免面板宽度变化把拖动坐标带偏。
- 拖动期间会在 `document` 捕获阶段压掉 `dragstart` / `selectstart`：
  悬浮球常压在 Topic 链接上，不压的话 Chrome 会对着底下的 `<a>` 启动原生
  HTML5 拖拽并立刻发 `pointercancel`，表现为"拖一下就卡住不动"。
- 只把**位置**（`{ left, top }`）存在 `IndexedDB meta.navUiState`
  （按账号命名空间）；旧版本存的 `{ right, top }` 会自动换算，升级后不跳位。
  悬停开合太频繁，不写折叠状态；窗口缩放时会重新夹回视口并重算展开方向。

**列表创建时间**（`ui/listMeta.js`）

- 只认能确定是"创建时间"的来源：`data-created-at` / `data-topic-created-at`，
  或 `td.age[title]` / `td.activity[title]` 里的「创建日期：…」。
  **故意不读 `data-bumped-at`** —— 那是最后活动时间，冒充创建时间语义就错了；读不到就不显示。
- 输出 `MM-DD HH:MM`，按年龄分三档：`is-fresh`（≤30 天）、
  `is-old`（30~90 天，橙色）、`is-ancient`（>90 天，灰化）。
- `render()` 只在值变化时写 DOM：`decorateRows` 自己也挂在 MutationObserver 上，
  无条件重写会导致 `render → mutation → decorateRows → render` 每 100ms 空转。
- Topic ID 来源：Topic 页取地址栏；预览弹窗取底部「打开原贴」链接
  `.ldp-f-open` 的 `href`（`/t/<id>`）。**每次点击现取**，
  因为同一个弹窗可能被复用来显示另一个 Topic。
- 点击后在弹窗内不会冒泡成"点背景关闭弹窗"；标记后给可撤销 Toast。
- 预览弹窗里点任一操作按钮，标记成功（写入本地状态）后自动关闭预览窗口：
  扩展端点击脚本自己的 `.ldp-close`（隔离世界读不到脚本挂在元素上的
  `overlay.ldpClose`）；油猴端与脚本同一主世界，优先直接调用 `ldpClose`
  以执行 abort 请求 / 停 tracker 等完整清理。拿不到 Topic ID 或写入失败时
  不关窗，避免用户误以为已经标记。
- 按钮本体放在**影子 DOM**：第三方「保存到本地」会把整段 `.cooked`
  `cloneNode` 进导出 HTML，且只移除它自己的按钮；影子树不会被复制，
  所以导出文件里不会残留我们的按钮，同时也不受站点 button 样式影响。

- 正文由 vendored 的「LinuxDo 增强阅读」引擎渲染（MIT，作者 Fashion，v1.8.7）：

  ③ 嵌套树 60 秒缓存 `NESTED_CACHE`（悬停预取命中它）；

- 关闭：×、Esc、点遮罩、标记成功后自动关；`closePreview()` 优先调 `overlay.ldpClose()`，
  扩展与油猴都在同一 JS 世界，能直接拿到引擎挂在元素上的 `ldpClose`。

- 点标题永远照常浏览 / 开预览，多选不拦截。
- 点按钮组任意位置 = 勾选 / 取消整条；再点一次只取消这一条，不退出。
- 双击同一枚同一位置 = 退出多选；默认退出仍是 Esc / 点球 / 点空白。
- 导航池子不再批量移入，只提示"拖到池子上松开"。

**实现过程中踩到并修掉的坑（避免以后重复）**

- `setPointerCapture` 不能放在 `pointerdown`：一旦捕获，click 目标变成整枚按钮组，
  内部三个按钮收不到点击，普通标记全部失效。只在真正越过 `DRAG_START_PX` 后捕获。
- `endDrag()` 里先 `drag = null` 再取 `targets` 会读到空，必须先存局部变量。
- `.ldfc-dragging` 里写 `top: auto !important` 会把 JS 内联高度写死的 `top` 一起压掉，
  表现为"按钮组只横向跟手、纵向不动"。只压 `right`，`top` 交给内联样式。
- 面板里新增的锚点 / 牵引线不是投放格，`hitTest` 与高亮必须只遍历 `.ldfc-drop-item`。

**验证边界（不要误读）**

- 光效、拖拽投放、双击退出、顶部翻边、搜索页不过滤、帖子页容器排除
  **全部只在本地 fixture 上验证**（`run-ui` 116 项）。
- 真实 linux.do 页面上的拖拽投放、真实触屏拖拽、面板在真实导航栏 / 楼层浮层下的
  层级遮挡 → `NOT TESTED`。
- 触屏（`pointerType === "touch"`）下的长按与拖拽没有真机证据 → `NOT TESTED`。

### 9.1 真实页面反馈后修掉的两个 bug

| 现象 | 根因 | 修法 |
|---|---|---|
| 帖子页的按钮组飘到页面中部 / 标题旁边（图：`#topic` 高度 50% 处、标题右侧各出现一枚） | `ROW_SELECTOR` 的兜底是 `[data-topic-id]`，而 Discourse 帖子页的 `#topic` / 主题头部容器也带这个属性，被当成"一行列表行"装饰了 | 新增 `KNOWN_ROW_SELECTOR` 白名单；`/t/` 与 `/search` 只认白名单行（推荐 / 相关仍在白名单内），兜底选择器不再对这两个页面生效 |
| 搜索页搜不到已经进了池子的帖子 | `core/filter.js` 的 `skipFiltering` 多了 `activePool === "HOME"` 前提：只要用户在搜索页点过池子，搜索就按池过滤 | 去掉了该前提，搜索页 / 帖子页**永远**不过滤，只保留光效 |

对应断言（`run-ui` 116 项里的最后两条）：

- `搜索页不过滤任何池子、只亮光效`：两条搜索结果，一条标成已屏蔽，
  把当前池切到「不感兴趣」后两张卡都必须可见，且只有被标记的那张带光效。
- `帖子页容器不会被当成列表行`：造一个 `#topic[data-topic-id]` 包住 600px 内容，
  `decorateRows()` 之后容器内 `.ldfc-actions` 数量必须为 0，也不能带 `ldfc-topic-row`。
